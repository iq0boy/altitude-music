# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # Astro dev server at localhost:4321
npm run build        # Static build to ./dist/ (also generates sitemap-index.xml)
npm run preview      # Serve the built site locally
npx astro check      # Type-check Astro & TS files
npm run sync:music   # Re-pull the Spotify playlist → src/content/music/*.md + public/audio/*.mp3
```

Node >= 22.12.0 is required. There is no test suite or linter; `npm run build` is the verification step — it fails on Zod schema errors in content files and on missing i18n keys.

`sync:music` **deletes and rewrites every file** in `src/content/music/` and seeds `bpm`/`genre`/`year`/`color` with defaults, so hand-edited values on those fields are lost. The playlist id is hard-coded at the top of `scripts/sync-music.mjs`.

To run the CMS locally: `npx @sveltia/cms-server` in one terminal, `npm run dev` in another, then open `http://localhost:4321/admin/` (writes to local files, no commits).

## Deployment

Netlify, auto-deploy on push to `main` (`netlify.toml` holds the build command, Node version and cache/security headers). CMS edits made by the studio also land directly on `main` as commits prefixed `cms:` — pull before starting work.

## Architecture

Static-rendered (SSG) Astro site for the Altitude Music studio in Louvain-la-Neuve. Three locales (`fr`, `en`, `nl`) routed via Astro's built-in i18n (`prefixDefaultLocale: true` — every page lives under `/fr/`, `/en/`, or `/nl/`). The root `/` redirects to `/fr/`.

### Rendering strategy: islands

Static, zero-JS sections are `.astro` components: `Nav`, `Hero`, `Marquee`, `Services`, `MediaGrid`, `About`, `Blog`, `Footer`, `SectionHead`. They render at build time and ship no JavaScript.

Interactive sections are React islands (`.tsx`) hydrated only when needed:

| Component | Hydration | Why |
|---|---|---|
| `Portfolio.tsx` | `client:visible` | Genre filter, HTML5 audio player over local preview MP3s, sticky now-playing bar |
| `Testimonials.tsx` | `client:visible` | Filter + submit form |
| `Booking.tsx` | `client:visible` | Calendar + slot picker wired to Cal.com public API v2 from the browser (`GET /slots`, `POST /bookings`, no key). Needs `settings.calUsername` and each service's `calEvent` slug; shows a contact notice otherwise |
| `Contact.tsx` | `client:visible` | Form + mailto, Leaflet map |
| `ServiceDetail.tsx` | `client:load` | Listens to `hashchange` for legacy `#service/<key>` deep links (modal) — must be live before user interaction |

Add new interactive sections as `.tsx` islands. Add new static sections as `.astro` components. Keep `client:load` only for things that respond to URL state on first paint.

### Content collections

Defined in `src/content.config.ts` (Astro v6 location — **not** the legacy `src/content/config.ts`). All collections use the `glob` loader:

- **`blog`** — one markdown file per language: `<slug>.<lang>.md`. Frontmatter must include `lang` and `postSlug` (we use `postSlug` instead of `slug` because the glob loader uses the `slug` field internally as the entry id, which would collide across languages). Pages are generated by `[lang]/blog/[slug].astro` from `getCollection('blog')`.
- **`music`** — one markdown per track (frontmatter only), normally generated by `sync:music`. Sorted by `sortOrder`.
- **`media`** — one markdown per video/image tile of the grid; files live in `public/media/`, or `src` is a YouTube link (rendered by the click-to-load `YouTube.astro` facade; `src/utils/youtube.ts` parses ids). Sorted by `sortOrder`.
- **`services`**, **`team`**, **`testimonials`** — JSON files (one per entry) holding **multilingual content** with shape `{ fr, en, nl }` per text field. `services` is a fixed set of 6 files keyed by `ServiceKey`; the filename = the key. Their `video` field is a YouTube id or URL (a `/shorts/` URL renders vertical); `image` is the hero visual of the service page, falling back to the video's YouTube thumbnail, then to the gallery gradient.
  Each service also gets a static, indexable page at `/<lang>/services/<key>/` from `[lang]/services/[key].astro` (same content as the modal, zero JS). Service cards, footer links and JSON-LD offers point to those pages.
- **`settings`** — a single file, `src/content/settings/site.json` (`heroVideo`, `ogImage`, `calUsername`), read with `getEntry('settings', 'site')`. An empty field means "use the coded default": `Hero.astro` falls back to `HERO_VIDEO_FALLBACK`, `BaseLayout.astro` to `/og-default.jpg`. Keep that fallback behaviour when adding settings.

To render markdown body, import `render` from `astro:content` and call `render(entry)` (the v5 `entry.render()` does not exist on glob-loaded entries).

### CMS (Sveltia, git-based)

`/admin/` is Sveltia CMS, served from `public/admin/` (`index.html` loads it from CDN, `config.yml` describes the collections). It commits straight to GitHub via Netlify's OAuth provider; setup is in `docs/cms-setup.md`.

**A collection field change must be made in three places**: the Zod schema in `src/content.config.ts`, the matching `fields:` block in `public/admin/config.yml`, and (for services/team/testimonials/settings) the interface in `src/data/services.ts`. `SERVICE_KEYS` is also duplicated between `content.config.ts` and `src/data/services.ts` — keep them identical. The `services` collection has `create: false` / `delete: false` in the CMS on purpose, since keys are used for routing.

Uploads go to `public/media/` (`media_folder`), except `music.audioSrc` which targets `public/audio/`.

### Data shape

- `src/i18n/{fr,en,nl}.json` — UI strings only (nav, section heads, form labels, `servicesUI`, `serviceDetail`…). Loaded statically via `src/i18n/utils.ts` (`getTranslations(lang)`); `Translations` is typed from `fr.json`. The shape is mirrored across all three files — when you add a new key to one, add it to all three. **Service/team/testimonial copy is NOT here** — it lives in the content collections above.
- `src/data/services.ts` — types only: `SERVICE_KEYS` + `ServiceKey` (stable ids referenced by `#service/<key>` routing, JSON-LD, `testimonial.service`) and the `ServiceData` / `TeamMember` / `TestimonialData` / `SiteSettings` interfaces. No data.
- Collections are loaded in `[lang]/index.astro` and passed down as props; React islands can't call `getCollection`, so they receive the data from the page. `Footer.astro` and `BaseLayout.astro` call `getCollection`/`getEntry` directly.

### Styling

`src/styles/global.css` is the single source of truth, imported once by `BaseLayout.astro`. CSS custom properties drive theming via HTML attributes set on `<html>` in the layout: `data-theme` (`dark`/`light`), `data-density` (`compact`/`regular`/`comfy`), `data-anim` (`on`/`off`). Custom fonts (Satoshi, Clash Display) live in `public/fonts/`; Google Fonts are pulled via `<link>` in the layout.

### SEO

`BaseLayout.astro` emits canonical URL, OG tags, hreflang links for all three locales (+ `x-default`), and a `MusicRecordingStudio` JSON-LD block whose aggregate rating is computed from the `testimonials` collection. `[lang]/index.astro` adds per-service `Service` nodes. The site URL is hard-coded as `https://altitudemusic.be` in `astro.config.mjs`, the layout and the index page. The sitemap integration auto-generates per-locale sitemaps.

### Scroll reveal

Elements with `class="reveal"` get a `.in` class added when they enter the viewport, via a small `IntersectionObserver` script at the bottom of `BaseLayout.astro`. No React needed for this.

### Legacy code

`website/` contains the original single-file React-via-CDN prototype. It is **not** part of the build. Keep it for reference only — make all changes under `src/`.

`docs/superpowers/` holds past specs and implementation plans (e.g. the media-upload feature); they document decisions already shipped.
